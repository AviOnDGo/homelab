# Security Policy

## Supported Versions

Security fixes are applied to the current `main` branch. Older releases and
previous deployment branches are not separately maintained.

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub's **Report a vulnerability** option if it is available. Otherwise,
contact the repository owner privately with:

- A description of the issue and affected service
- Steps to reproduce it
- The potential impact
- Any suggested mitigation

Do not include credentials, access tokens, private hostnames, or other sensitive
homelab details in the initial report.

## Response

The repository owner will acknowledge valid reports as soon as practical,
assess the impact, and coordinate remediation before disclosing details.

## Scope

Security reports may cover tracked configuration, automation, scripts,
container images, GitHub Actions workflows, and infrastructure definitions.
Runtime configuration and third-party services outside this repository are
excluded unless the repository exposes an integration risk.
